# W6 评测报告：单 Agent vs 多 Agent（分解 / 并行检索 / 核验）

> 生成时间 2026-10-30 13:30（Asia/Shanghai）。本报告只使用 `dataset_version=4d1c7846`
> 的记录；跑批代码 `2923174`（A2）与 `5585a83`（A0/A1），两者 `src/` 无差异。
> 汇总代码 `db810e6`（仅指标口径修复，不影响已有记录）。

## 0. 结论先行

| 配置 | n | 有报告 | 忠实度 | 覆盖率 | F1 | 检索命中 | 论断落锚失败率 | 引用率 | 成本 | 墙钟 |
|---|---|---|---|---|---|---|---|---|---|---|
| **A0** 单 agent | 10 | 7 (70%) | 0.5038 | 0.7809 | 0.5708 | 57% | **46%** | 70% | ¥0.73 | 541s |
| **A1** 多 agent，无核验 | 10 | 10 (100%) | 0.5780 | 0.7962 | 0.6560 | 85% | 6% | 81% | ¥3.09 | 1383s |
| **A2** 全链路 | 10 | 10 (100%) | **0.7046** | **0.9029** | **0.7847** | 92% | 6% | 95% | ¥4.13 | 1499s |

1. **多 agent 的第一价值不是"写得更好"，而是"交得出报告、论断落得了地"**：
   A0 有 3/10 题因为最终回答不是合法 JSON 直接 0 论断（`invalid_shape`），
   另有 46% 的论断因句柄幻觉/引文找不到被剔除；A1/A2 的落锚失败率都是 6%。
2. **核验环节（A2）是唯一大幅抬忠实度的部件**：A1→A2 忠实度 +12.7 分、覆盖 +10.7 分，
   成本只多 34%（¥3.09 → ¥4.13）。
3. **不建议上线无核验的多 agent 配置**：A1 的报告率与检索都到位了，但忠实度仍在 0.58，
   与 A0 同一量级；"多 agent 自动更可信"不成立。

## 1. 研究问题

- **H1**：把任务分解成多个并行 researcher，是否提升检索覆盖率与报告成功率？
- **H2**：加一层 Verifier（逐条论断核验）是否提升忠实度（faithfulness）？
- **H3**：这些提升值多少钱（token / 人民币 / 墙钟）？

## 2. 方法

### 2.1 数据集

`eval/dataset/w6-10q.yaml`，10 题（e011–e020），版本 `4d1c7846`，`as_of_date=2026-11-01`。
题型覆盖：技术机制、时间线、法规、诉讼、选型对比。每题给定 5–7 个参考要点（key points），
要点由人工前置撰写、经"外核修正"（e015 补第三巡回 2025-10 维持、e017 补 Digital Omnibus 延期）。

### 2.2 三个配置

| 配置 | Planner | Researcher | Verifier | Writer |
|---|---|---|---|---|
| A0 | —（单 agent 一次 loop，有工具） | — | — | — |
| A1 | ✓（分解子问题） | ✓（并行） | — | ✓ |
| A2 | ✓ | ✓ | ✓（逐条论断核验） | ✓ |

三者共用同一套测量机械：论断走 `build_claims`（snippet 句柄 → 句级锚定，quote 必须能在
原文中逐字定位），报告走 `build_report`（`[[n]]` 协议 + 程序化 citation_map）。

### 2.3 指标

- **忠实度 faithfulness** = supported / (supported + partial)，分母是"报告实际引用且被判定的论断"；
  未核验（unverified）单列，不进分子分母。
- **覆盖率 coverage** = 被报告"实质写到"的参考要点数 / 要点总数（judge 逐点判定，
  evidence 只允许来自 citation_map）。
- **F1** = 忠实度与覆盖率的调和平均；两者成对报告，单看一个都会误导。
- **漏斗**：检索命中 → 论断抽取 → 核验通过 → 引用。论断落锚失败率 = 失败数 /（失败数 + 保留数）。
- **引用率** = 报告实际引用的 distinct 可引用论断数 / 可引用论断数。

### 2.4 judge

- 模型：`glm-5.3-flash`（智谱），与生产链路（DeepSeek-V4.1-Flash-1017）**跨厂商**；
- 档位：`reasoning_effort=high`（GLM-5.3 强制思考，`temperature=0.0` 只能"尽力"）；
- rubric 版本：`#j2`（判定口径 + 两条边界规则：引文外编号/名称、无歧义指代）；
- 忠实度判定只依据 `quote`，不用外部知识；覆盖率判定只依据给定材料，evidence 表外编号一律过滤。

### 2.5 复现参数

| 项 | 值 |
|---|---|
| 数据集版本 | `4d1c7846` |
| 生产 prompt | `p1` |
| judge | `glm-5.3-flash#j2`，effort=`high` |

## 4. 分析

### 4.1 A0 的"忠实度"是被筛选过的

A0 的 0.5038 只算在**幸存的 43 条论断**上（原始尝试 79 条）。46% 的论断在落锚阶段被剔除，
其中 21 条是句柄幻觉——模型记不住自己看过的片段编号。幸存论断的引文更可能"好定位"，
所以 A0 的忠实度既不能读成"更爱胡说"，也不能读成"更可信"；**分母不同，不可直接比**。

### 4.2 核验是忠实度的来源

A1→A2 的忠实度提升（0.578 → 0.705）与 partial 占比同步上升（judge 判 partial 29.3%，
253 supported / 105 partial / 0 unsupported）。核验的作用不是"删掉坏句子"（A2 未核验 0 条），
而是把 unsupported 的论断挡在引用之前、逼 writer 只引用可支撑的论断——引用率也从 81% 升到 95%。

### 4.3 难题上的检索缺口是共同的

e015（AI 与版权判例）三组都没拿到 Thomson Reuters v. Ross、第三巡回 2025-10 维持、
NYT v. OpenAI 这三条；A2 的 3/7 覆盖率不是 judge 判错，是报告里确实没有。A1 在 e019
（Redis 许可证）也出现 `retrieval_low`（覆盖 0.33）。**并行检索不解决"搜不到"**，
只解决"搜到了但没写进报告"。

### 4.4 成本

A2 每题 ¥0.41，其中 judge 约 ¥0.02–0.05（high 档思考 token 计入输出）。
相对 A1 的 +34% 成本换来 +12.7 忠实度、+10.7 覆盖，是本轮性价比最高的一档；
相对 A0 的 ×5.7 则主要买"报告率 70%→100%"和"落锚失败 46%→6%"。

## 5. 威胁效度（必须随结论一起读）

1. **没有真人校准**。judge 与人工的一致性只做过 agent 演练（非盲，90%，kappa 0.80），
   不得当作人工校准结论。可替代的量化证据：同一批 30 条连判 3 次 **30/30 完全一致**，
   说明判定可复现、分歧来自口径而非噪声。盲标表已入库（`eval/calibration/`），人力可补。
2. **单次运行、无随机种子**。n=10 是题数不是重复数；同一题在不同 run 间波动明显
   （e011 在 j2@high 的两次运行忠实度 0.6957 / 0.7632），单题级结论不可用，
   只能读配置级均值。
3. **分母不可比**：A0 43 条论断 vs A2 383 条；A0 的忠实度只在 7 题上计算。
4. **引用率口径不同**：A0/A1 无核验阶段，其"可引用"是兜底判据（默认 supported），
   70%/81% 与 A2 的 95%（只含已核验论断）不是同一把尺。
5. **judge 严格口径**：claim 比 quote 多出内容即判 partial；GLM-5.3 强制思考，
   `temperature=0.0` 不被保证（实测同输入 3 次结果一致，但机制上不保证）。
6. **模型真身拿不到**：API 只回 `deepseek-flash`，版本 `DeepSeek-V4.1-Flash-1017`
   只能从发布信息侧确认，`model_snapshots` 记的是别名。
7. **时间截面**：`as_of_date=2026-11-01`，搜索结果随时间漂移；e015/e017 这类
   时效性强的题对检索日期敏感。

## 6. 结论

1. 多 agent 的必要性首先体现在"交付可靠性"：报告率 70%→100%，论断落锚失败 46%→6%。
2. 忠实度的提升来自核验层，不是并行检索：A1 与 A0 的忠实度同一量级（0.58 vs 0.50）。
3. 覆盖率的提升主要发生在 A1（0.78→0.80 已接近饱和），A2 的 +10.7 来自"把已检索到的
   证据真正写进报告"。
4. 生产建议：用 A2；如果成本敏感，砍并行度而不是砍核验。
