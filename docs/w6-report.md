## 1. 研究问题

- **H1**：把任务分解给多个并行 researcher，是否提升检索覆盖与报告成功率？
- **H2**：加一层 Verifier（逐条论断核验），是否提升忠实度？
- **H3**：这些提升值多少钱（token / 人民币 / 墙钟）？

## 2. 方法

### 2.1 数据集

`eval/dataset/w6-10q.yaml`，10 题（e011–e020），版本 `4d1c7846`，`as_of_date=2026-11-01`。
题型覆盖技术机制、时间线、法规、诉讼、选型对比；每题 5–7 个参考要点，经"外核修正"。

### 2.2 三个配置

| 配置 | Planner | Researcher | Verifier | Writer |
|---|---|---|---|---|
| A0 | —（单 agent 一次 loop，有工具，max_turns=10） | — | — | — |
| A1 | ✓ | ✓ 并行 | — | ✓ |
| A2 | ✓ | ✓ 并行 | ✓ 逐条核验 | ✓ |

A0 允许**一次纯格式重试**：研究结束后若最终回答不是合法 JSON，补一次"不要重新检索、
只把上面的答案按契约输出"的调用（`4cc243a`）。没有这一步，A0 会因为收尾格式失败被记成
"0 论断 + FAILED"，把格式能力算进研究能力——这是对基线的不公平。

三者共用同一套测量机械：论断走 `build_claims`（snippet 句柄 → 句级锚定，quote 必须能在
原文逐字定位），报告走 `build_report`（`[[n]]` 协议 + 程序化 citation_map）。

### 2.3 指标

- **忠实度** = supported / (supported + partial)，分母是"报告实际引用且被判定的论断"；
  未核验单列，不进分子分母。
- **覆盖率** = judge 判定"报告实质写到"的参考要点数 / 要点总数，evidence 只允许来自 citation_map。
- **F1** = 两者的调和平均（逐题算再平均）。
- **落锚失败率** = 失败论断 /（失败 + 保留）。
- **引用率** = 报告引用的 distinct 可引用论断 / 可引用论断。

### 2.4 judge

- `glm-5.3-flash`（智谱），与生产链路（DeepSeek-V4.1-Flash-1017）跨厂商；
- 档位 `reasoning_effort=high`（GLM-5.3 强制思考）；
- rubric `#j2`：忠实度只依据 quote、不用外部知识；两条边界规则（引文外编号/名称、无歧义指代）；
- 覆盖率 evidence 表外编号一律过滤，过滤后为空则如实降级。

| A0 无重试 | 43 | 36 | 46% | unknown_snippet 21、quote_not_located 12、invalid_shape 3 |
| A0 重试 #1 | 80 | 20 | 20% | quote_not_located 18、unknown_snippet 2 |

## 4. 分析

### 4.1 覆盖率提升来自"写进去"，不是"搜得多"

A1 检索命中 85%、A2 92%，但 A0 只有 65%；覆盖率差距（共同题集 0.81/0.90/0.95）
与论断数（78/366/383）同步。多 agent 把"读到的东西"变成"可用论断"再变成"写进报告"，
单 agent 每题只有 4–12 条论断，覆盖面天然受限。

### 4.2 缺失数据偏差：为什么"自有样本均值"不可直接比

A0 在 e015、e019 上没有报告，这两题恰好是 A1/A2 的短板（e015 覆盖 0.43、e019 0.33）。
于是：

- 自有样本均值里，A0 的分母排除了自己最差的两题 → 覆盖 0.8083；
- A1 必须带着这两题算 → 0.7962，反而更低；
- 只用共同 8 题，A1 的覆盖是 0.9000，比 A0 高 9.2 分。

**结论：跨配置比较必须用共同题集，或把失败题记为 0。** 否则"谁失败得多，谁的数字更好看"。

### 4.3 核验是忠实度的来源

A1→A2 忠实度 0.6287 → 0.7046（共同题集），引用率 81%→95%，核验未通过 2 条（e017）。
核验的作用不是"删坏句子"，而是把 unsupported 挡在引用之前、逼 writer 只引用能支撑的论断。
judge 在这批 358 条被引论断上给出 253 supported / 105 partial / 0 unsupported——
partial（"引文只支持一部分"）才是主要错误面。

### 4.4 难题上的检索缺口是共同的

e015（AI 与版权判例）三配置都没拿到 Thomson Reuters v. Ross、第三巡回 2025-10 维持、
NYT v. OpenAI；A2 的 3/7 不是 judge 判错，是报告里确实没有。A1 在 e019（Redis 许可证）
也 `retrieval_low`（覆盖 0.33）。**并行检索不解决"搜不到"，只解决"搜到了没写进报告"。**

### 4.5 成本

A2 每题 ¥0.41（judge 约 ¥0.03）。相对 A1 的 +34% 换 +7.6 忠实度 / +5.0 覆盖；
相对 A0 的 ×10.6 主要买"覆盖率 +14 分"和"论断量 5 倍"。

## 5. 威胁效度（必须随结论一起读）

1. **无真人校准**。judge 与人工一致率只做过 agent 演练（非盲，90%，kappa 0.80），
   不得当人工校准结论。替代证据：同批 30 条连判 3 次 **30/30 完全一致**——判定可复现，
   分歧来自口径而非噪声。盲标表已入库（`eval/calibration/`）。
2. **缺失数据偏差**（§4.2）：自有样本均值会奖励"失败得多"的配置；本报告已给共同题集修正。
3. **单次运行**：n=10 是题数不是重复数。A0 三次运行报告率 70/90/80%、覆盖 0.70–0.81；
   A2 只跑过一次。配置级结论比单题结论稳，但仍不是重复实验。
4. **分母不可比**：A0 78 条论断 vs A2 383 条；忠实度只在被引论断上算，论断越少越容易"精"。
5. **引用率口径**：A0/A1 无核验阶段，可引用性用兜底判据（默认 supported），
   80%/81% 与 A2 的 95%（只含已核验论断）不是同一把尺。
6. **judge 严格口径**：claim 比 quote 多出内容即 partial；GLM-5.3 强制思考，
   `temperature=0.0` 不被保证（实测同输入 3 次一致，但机制上不保证）。
7. **模型真身缺失**：API 只回 `deepseek-flash`，版本 `DeepSeek-V4.1-Flash-1017`
   只能从发布信息侧确认。
8. **时间截面**：`as_of_date=2026-11-01`，搜索结果随时间漂移；e015/e017 对检索日期敏感。

9. **环境失效与模型方差混叠**（2026-10-31 补跑实测）：检索层失效（Tavily 月末配额耗尽的诊断签名=检索词已发出+抓取 0+tool_failure_streak）会让二次观测变成 (模型, 降级环境) 的联合观测——跨时间跑批的方差读数必须先核对检索层健康度。本报告主表数字取自首轮（健康窗口），未受影响。

## 6. 结论

1. 多 agent 的分解 + 并行带来的是**覆盖率**（共同题集 +9.2）与**论断量**（×4.7），
   不是忠实度——A1 与 A0 在共同题集上忠实度打平（0.6287 vs 0.6285）。
2. 忠实度的提升来自**核验层**：+7.6 分，且引用率从 81% 提到 95%，成本只多 34%。
3. 生产建议：用 A2。若成本敏感，砍并行度（A1）会先丢覆盖率，砍核验会丢忠实度。
4. 评测方法建议：跨配置比较一律用共同题集或失败记 0；自有样本均值只能用于单配置报告。
5. A0 的失败模式是**句柄幻觉**，不是研究能力；给它一次格式重试是公平基线的最低要求。
6. **上述第 2 条（核验层 +7.6）只在 W6 首轮、检索正常的窗口成立。** 复跑轮方向反转，
   95% CI 重叠；n=10 下 A2 相对 A1 的差异不可判定，见 §9。

## 8. 成本超线

> 补记于 2026-10-31。数据源：`eval/reports/eval-20261031002013.md`（2026-10-31 00:20，
> A1/A2 各 10 题，code `5e72117`，数据集 v4d1c7846）。本节不改评测代码、不重跑。

### 8.1 超线事实与数字

该报告表头成本列：A1 **¥1.02**、A2 **¥0.92**。PLAN 的成功标准是"单任务 ≤ 1 元"；
按报告读数，**A1 已越过该线**。

**口径校正（必须一起读）**：`eval/runner.py` 的 `_rows()` 对 10 题的逐题 `cost_cny`
求和，所以表头这一列是**本轮 10 题合计**，不是单题成本；摊到单题 A1 ≈ ¥0.102、
A2 ≈ ¥0.092，按 PLAN 的单任务口径并未超线。问题在于表头没有标注"合计"——
直接把该列当单任务成本就会读出"超线"。两种读法指向同一个待修项：
**成本列必须显式标注口径（合计 / 单题），否则成功标准无法被稳定核对。**

### 8.2 超线主要由哪两题贡献

按 prompt + completion token 排序（A1，code `5e72117`）：

| 排名 | 题号 | prompt tokens | completion tokens | 合计 | 该题成本 | 占 A1 批次成本 |
|---|---|---|---|---|---|---|
| 1 | e017 | 101,903 | 15,632 | 117,535 | ¥0.1941 | 19.0% |
| 2 | e011 | 72,177 | 10,365 | 82,542 | ¥0.1299 | 12.7% |

两题合计 200,077 tokens、¥0.3240，占 A1 本轮 ¥1.02 的 **31.7%**。
对照 A2 的前两题是 e014（84,753+14,599=99,352）与 e017（77,127+11,477=88,604）。

注意：本轮 3 题 `run_failed`（A1 e012/e015/e016），失败题 token 很低（e015 仅 20,579），
不是省了钱，而是检索 0 命中后管线提前放弃——**用失败换来的低成本不能当优化成绩**。

### 8.3 修复方向（本次未实施）

PLAN buffer 第 1 项（W7 起）：**三级缓存 + 模型分级**——

- **三级缓存**：搜索全量缓存 → 页面/片段缓存 → 论断/报告层缓存，跨轮复用，
  直接砍掉重复检索与重复抽取；
- **模型分级**：researcher / verifier 用便宜模型，planner / writer 用强模型。

**本次未实施**：Tavily 月末配额耗尽，检索层无法恢复到健康窗口，缓存命中率与分级后的
成本都**无法验证**；在不可复现的检索层上上线降本改动，数字不可信。

A2 的忠实度区间完全被 A1 的区间包住；覆盖率、F1 同样大面积交叠。

### 9.4 结论

**在 n=10 的样本量下，A2 相对 A1 的差异不可判定；W6 报告的 +7.6 只能作为单轮点估计，
不能作为结论。**

复跑轮的退化不是随机的：trace 判读显示 **3~5 题检索命中率为 0**（逐题明细里 A1 为
e012/e015/e016，A2 为 e015/e016/e018），属检索层退化（Tavily 月末配额耗尽的诊断签名：
检索词已发出 + 抓取 0 + `tool_failure_streak`）。因此该轮是 **(模型, 降级环境) 的联合观测**，
不能拿来检验配置差异。

另：报告头"有报告率"与逐题明细不一致——表头 100%，实际 3 题 `run_failed`、无忠实度。
该列口径已知失真，读数请以逐题明细为准。

### 9.5 补救方案

1. **配对设计**：同题比较 A1 vs A2 的差值分布（配对 t / Wilcoxon），消掉题目难度方差；
2. **扩样**：题数扩到 ≥30，或对同一题集做多轮重复，把配置效应从轮次/环境方差里分离出来；
3. **跑批前先做检索层健康检查**（命中率门槛 + `tool_failure_streak`），不健康的轮次
   只记为环境观测，不进消融结论。
